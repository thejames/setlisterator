# Auditioning streams through the app, not straight from Plex

The app lets you **audition** a candidate track (see `CONTEXT.md`) before selecting it, on the preview screen and in library search results. The obvious implementation is to point an `<audio>` element straight at a tokenized Plex URL — that is what Plex Web itself does, it needs no server code, and HTTP `Range` gives an accurate scrubber for free. We decided instead to **detect, once per browser session, whether the browser can reach Plex directly, and proxy the audio through the app when it can't**.

The reason is topology, not secrecy. The app's two deployment modes disagree about who can reach Plex: `web.py` binds `127.0.0.1` for local runs, but the published Docker/Unraid deployment binds `0.0.0.0:5001` and resolves `PLEX_BASEURL` *inside the container*. Handing that same URL to a browser assumes the browser sits on the Plex LAN. Accessed over Tailscale — the author's normal mode — it does not, and playback fails silently while the rest of the app works fine. Same-origin audio works wherever the app works. A future HTTPS reverse proxy would also hard-block an `http://` Plex URL as mixed content, with no user override for media elements.

We explicitly do **not** justify this on the grounds of hiding the Plex token. The token is a bearer credential that Plex Web puts in URLs routinely, and the operator enters it themselves in the container config. Keeping it server-side is a side benefit, not the rationale — do not "restore" the direct path on the argument that the token was never really secret.

## Considered options

- **Direct tokenized Plex URL.** Rejected: breaks whenever the browser isn't on the Plex LAN, which is the primary access mode here.
- **Always proxy.** Rejected: on the LAN it burns a server thread per stream to buy nothing, since the browser could have fetched the bytes itself.
- **Fall back on playback error instead of probing up front.** Rejected: an unroutable address takes ~30s to fail, so the first click would stall before recovering. The probe runs on page load and is cached in `sessionStorage`.

## Consequences

- The reachability probe must be a real HTTP request (`fetch`, `no-cors`, ~2s abort). A TCP-level check is not sufficient — under Tailscale's userspace networking a TCP connect succeeds against a host that never answers HTTP, so a socket-level probe reports reachable and sends playback down the path that silently fails.
- Transcoding is a **codec-compatibility fallback only**, never a bandwidth strategy: direct-stream anything Chrome plays natively (MP3, AAC, FLAC, Opus), transcode the rest (ALAC, WMA, APE) at ≤256k. A 2000-track census of the library found FLAC 1172, MP3 749, AAC 53, **ALAC 26** — so this branch is required, not speculative, though it serves ~1% of tracks. ALAC in `.m4a` is the one common format Chrome refuses and Safari accepts. Dropping the fallback would make those albums silently unauditionable. Transcoded streams are chunked with no `Content-Length`, so `duration` is `Infinity` and the scrubber is approximate — `/audition` returns the mode it chose so the UI can say so rather than appear broken. Verified against the live server (Plex 1.43.3): the direct path returns `Accept-Ranges: bytes` with a `Content-Length` and honours range requests with `206`/`Content-Range`; the transcode path returns `Accept-Ranges: none`, `Transfer-Encoding: chunked`, and measured ~258 kbps against a `maxAudioBitrate` of 256. A transcoded audition therefore cannot be seeked at all through the proxy, since there is no upstream range support to forward — not merely approximate, absent.
- The proxy path is load-bearing under the shipped `gunicorn --workers 1 --threads 4`: each open stream holds one of four threads. Stopping an audition must **close the connection**, not merely pause the element, which leaves the socket open. Combined with the one-audition-at-a-time rule this bounds concurrency to roughly one stream per tab.
- Auditioning is **best-effort**, like the playlist poster (ADR-0002): a dead Plex, a deleted track or a failed transcode surfaces inline on the audition element and never blocks, alters or undoes a selection, and never touches the create path.
- URLs are minted on demand by `GET /audition/<rating_key>`, backed by a core seam (`audition_source`) so the codec→mode decision stays testable as pure logic and out of `web.py`. Nothing is added to the match IR, the history JSON, or the form round-trip.
- The probe, the roaming player element and the stop-on-change rules are browser behaviour, and this repo has no JS test harness — they are verified by clicking through the app, not by CI.
